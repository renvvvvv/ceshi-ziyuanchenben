# 数据中心测试验证管理平台 · 内网部署说明

> 版本：2026-09-11 ｜ 适用于将平台从公网环境迁移至内网/隔离环境的部署

---

## 一、环境要求

| 组件 | 要求 | 说明 |
|---|---|---|
| 服务器 | Linux x86_64，4 核 / 4GB 内存 / 40GB 磁盘 | 实测 100 并发零错误（P99 125ms） |
| Docker | 20.10+ 及 Docker Compose v2 | 唯一运行时依赖 |
| 图纸路由模块（可选） | 宿主机 Python 3.8+、ODA File Converter、systemd | DWG 转换在宿主机执行，见第六节 |

内网**无公网出口**时的功能影响（重要，先读）：

| 功能 | 是否需要公网 | 内网可用性 |
|---|---|---|
| 全部页面/项目/考勤/资源配置/图纸路由 | 否 | ✅ 完整可用（图纸管线纯本地） |
| 账号密码登录 | 否 | ✅ 可用（推荐内网主用） |
| 飞书一键登录 | 是（浏览器与后端都要访问 open.feishu.cn） | ❌ 失效，切换账密登录 |
| AI 测试专家 / 报告审核 AI / 故障日志 AI 解析 | 是（智谱 open.bigmodel.cn） | ❌ 失效，其余功能不受影响 |
| 智谱 Embedding 向量检索 | 是 | ❌ 降级为关键词检索 |

结论：纯隔离内网下平台核心业务功能完整可用；AI 类功能需要公网出口或内网代理（HTTP_PROXY）才能使用。

## 二、部署步骤

### 1. 解压部署包

```bash
# 部署包 = 项目源码（含 docs/、database.dump）
tar xzf ceshi-ziyuanchenben-inner.tar.gz -C /opt/test-platform
cd /opt/test-platform
```

### 2. 配置环境变量

```bash
cat > .env << 'EOF'
DB_PASSWORD=<设置一个强密码>
# 以下公网 Key：内网有出口/代理时填写，纯隔离可不填（AI 功能关闭）
ZHIPU_API_KEY=
MINIMAX_API_KEY=
# 飞书：内网不适用可留空（登录页飞书按钮将不可用）
FEISHU_APP_ID=
FEISHU_APP_SECRET=
FEISHU_REDIRECT_URI=
EOF
chmod 600 .env
```

### 3. 启动服务

```bash
docker compose up -d
# 首次会拉取/构建镜像，等待 postgres healthy + backend healthy
docker compose ps   # 三个容器应全部 Up (healthy)
```

首次启动时后端会自动建库建表（init.sql 幂等执行）。此时是一个**空库**。

### 4. 恢复数据库（从包内 dump 恢复公网环境的全部数据）

```bash
docker cp database.dump test-platform-postgres-1:/tmp/dump
docker exec test-platform-postgres-1 pg_restore -U postgres -d test_platform --clean --if-exists --no-owner /tmp/dump
docker exec test-platform-postgres-1 rm /tmp/dump
# 重启后端刷新内存缓存
docker compose restart backend
```

恢复内容包含：用户与权限矩阵、项目、考勤、知识库与向量索引、图纸任务记录、资源配置数据（含已交付存档）、故障日志快照、AI 学习库等全部数据。

> 数据文件（server/data/*.json：会话/学习库/飞书用户缓存）如需同步迁移，把公网服务器 `/root/test-platform/data/` 目录拷贝到内网同位置并 `docker compose restart backend`。

### 5. 验证

```bash
curl http://127.0.0.1/api/health          # {"status":"ok"}
# 浏览器访问 http://<内网IP>/ ，用 admin 账号登录（密码见第七节）
```

## 三、内网登录方式调整

- **推荐**：全员使用账号密码登录。公网环境的飞书用户信息已随 database.dump 迁移（feishu-users），但内网无法走飞书 OAuth。
- **批量建号**：参照 `data/local-users.json` 的格式，按公网用户名单批量添加本地账号（scrypt 哈希），或联系开发批量生成。
- 登录页两种方式并列展示；飞书不可用时点击会失败但不影响账密登录。

## 四、备份策略（内网延续）

公网环境的备份体系建议照搬：

```bash
# 每日 03:00 全量备份（数据库 + data + uploads + 图纸长期归档）
0 3 * * * /bin/bash /opt/test-platform/scripts/backup.sh >> /opt/test-platform/backups/backup.log 2>&1
# 每周日 04:00 清理 7 天前备份
0 4 * * 0 /bin/bash /opt/test-platform/scripts/cleanup-backups.sh
```

脚本随源码在 `scripts/` 目录，部署后 `chmod +x` 并安装 crontab 即可。恢复方法见 backup.sh 头部注释（本包 database.dump 的恢复步骤即演练过的标准流程）。

## 五、nginx 与安全

- 端口：仅 80 对内网开放；数据库 5432 与后端 3001 已绑定 127.0.0.1，不对外。
- 敏感路径（.env/.git 等）已配置 404。
- 上传限额 600MB（图纸整包）。
- 如需 HTTPS，在内网负载均衡/网关上终止 TLS 即可（应用无硬编码协议）。

## 六、图纸路由模块部署（可选）

图纸模块依赖宿主机工具链（容器内零依赖设计）：

1. 安装 ODA File Converter（deb 包）+ Python3 + `pip install ezdxf openpyxl`；
2. `scripts/drawing-runner.py` 部署为 systemd 服务（unit 文件见 scripts/drawing-runner.service 示例），环境变量 `DRAWING_PIPELINE` 指向 `/root/drawing-tools/scripts/run_pipeline.py`；
3. 技能脚本（run_pipeline/mine_lv/gen_routing 等）在部署包 `scripts/` 内，拷贝到 `/root/drawing-tools/scripts/`；
4. 黄金基准回归：`golden_compare.py`（7# 楼基准已含）。

## 八、常见问题

**Q：启动后 backend 反复重启？**
查 `.env` 的 DB_PASSWORD 是否与卷内已有 postgres 密码一致（沿用旧数据卷时必须用原密码）。

**Q：AI 问答报"配置缺失"？**
内网无公网导致，属预期；配置 ZHIPU_API_KEY 且网络可达后自动恢复。

**Q：图纸上传后一直排队？**
宿主机 drawing-runner 服务未启动，`systemctl status drawing-runner` 排查。

**Q：想迁移到新服务器？**
停服 → 拷贝整个部署目录 + `docker volume`（pg_data）→ 新机 `docker compose up -d`。或用 backup.sh 产物按第四节恢复。
