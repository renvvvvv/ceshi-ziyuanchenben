## 文档说明

本文档为智航万恒测试验证管理平台的**分阶段交付计划**，以项目实际业务需求为导向，将整体建设分为**四个阶段**逐步推进。每个阶段设定明确的里程碑目标、交付成果物和验收标准，确保项目在可控节奏下高质量交付。

## 第一阶段：基础平台搭建

**预计工期**：约 18 个工作日（2-3周）  
**开始时间**：Day 1  
**核心目标**：完成仪表盘和测试人员池两大核心模块的开发上线，实现测试资源可视化管理和人员状态自动化追踪。

### 1.1 阶段目标

本阶段聚焦于**平台基础设施**和**人员管理**两个核心模块，目的是让管理者能够**一眼看清**当前测试资源的使用情况和人员工作状态。

### 1.2 里程碑分解

#### 里程碑 1.1：仪表盘上线

**完成标准**：管理者打开平台首页，即可看到数据中心测试运营的核心数据。

| 功能点 | 详细描述 | 优先级 |
|--------|---------|--------|
| 项目状态分布 | 饼图展示：准备中/进行中/待验收/已完成，数量+百分比 | P0 |
| 项目进度概览 | 柱状图展示各项目当前进度百分比，直观对比 | P0 |
| IT产出统计 | 数字卡片展示总IT产出量、本月新增、当年累计 | P0 |
| 合同金额统计 | 总合同金额、已回款金额、待回款金额（预计）| P1 |
| 今日值班人员 | 显示当天值班人员姓名+联系方式 | P1 |
| 最近操作动态 | 实时显示最新项目变更、人员调度记录 | P2 |
| 快捷入口 | 跳转至项目管理、人员池、历史项目、知识库 | P0 |

#### 里程碑 1.2：测试人员池功能完善

**完成标准**：测试人员池能够清晰展示所有测试人员的状态、当前项目和技能档案，支持快速调度。

| 功能点 | 详细描述 | 优先级 |

| 实时项目显示 | 卡片底部显示当前进行中项目的名称和起止时间 | P0 |
| 人员筛选 | 支持按状态（全部/空闲/测试中）、工种分类筛选 | P0 |
| 人员搜索 | 支持按姓名、工号精准搜索 | P0 |
| 人员档案编辑 | 点击编辑弹窗，修改姓名、工号、状态、技能证书 | P0 |
| 批量指派 | 勾选多名空闲人员，一次性指派到同一项目 | P0 |
| 转为空闲 | 编辑弹窗底部「转为空闲」按钮，一键清空项目+改状态 | P0 |

- [ ] 仪表盘数据加载时间 < 2秒

## 第三阶段：数据中台建设

**预计工期**：约 15 个工作日（2-3周）  
**开始时间**：第二阶段上线后第 2 天  
**核心目标**：从前端 mock 数据切换至真实数据库，完成数据持久化存储，实现跨模块数据联动和历史项目链接跳转功能。

---

### 3.1 阶段目标

本阶段是**技术架构升级**的关键节点，将平台从"原型展示"阶段推进到"生产可用"阶段，实现数据的**持久化存储**和**跨模块联动**。

### 3.2 里程碑分解

#### 里程碑 3.1：数据库设计与搭建

**完成标准**：完成生产级数据库设计，从 mock 数据平滑迁移到真实数据库。

| 功能点 | 详细描述 | 优先级 |
|--------|---------|--------|
| 数据库选型 | 推荐使用 PostgreSQL（公司 AI 团队已有经验），或 MySQL | P0 |
| 表结构设计 | 设计以下核心表：projects / historical_projects / team_members / test_scripts / test_submissions / test_signoffs | P0 |
| 字段完整定义 | 所有字段类型、约束（NOT NULL / UNIQUE / DEFAULT）、索引设计 | P0 |
| 数据迁移脚本 | 将 mock.ts 中的所有模拟数据迁移到数据库，支持增量同步 | P0 |
| 连接池配置 | 配置数据库连接池（推荐 HikariCP），并发连接数 ≥ 50 | P0 |
| 备份策略 | 全量备份（每日）+ 增量备份（每小时），异地容灾 | P0 |
| 敏感数据加密 | 人员手机号、身份证等敏感字段 AES 加密存储 | P1 |

#### 里程碑 3.2：后端 API 开发

**完成标准**：完成所有业务模块的 RESTful API，支持前端所有 CRUD 操作。

| 功能点 | 详细描述 | 优先级 |
|--------|---------|--------|
| 项目管理 API | POST/GET/PUT/DELETE `/api/projects`，支持分页、筛选、排序 | P0 |
| 历史项目 API | POST/GET/PUT/DELETE `/api/historical-projects` | P0 |
| 人员池 API | GET `/api/members`、PUT `/api/members/:id`、批量指派 `POST /api/members/batch-assign` | P0 |
| 仪表盘 API | GET `/api/dashboard/stats`，返回聚合统计数据 | P0 |
| 文件上传 API | POST `/api/upload`，支持文件上传到对象存储 | P1 |
| 接口文档 | Swagger/OpenAPI 3.0 接口文档，供前端和后续维护使用 | P1 |
| 错误处理规范 | 统一错误响应格式 `{ code, message, detail }`，所有接口有 try-catch | P0 |
| SQL 注入防护 | 所有数据库查询使用参数化查询，禁止字符串拼接 | P0 |

## 第四阶段：测试脚本线上化

### 4.1 阶段目标

本阶段是平台**核心价值的最终体现**，将数据中心现场测试的**全部纸质流程**迁移到线上，彻底告别传统的纸张+笔+签字板的作业模式。

### 4.2 里程碑分解

#### 里程碑 4.1：脚本模板库建设

**完成标准**：将公司现有的40+个测试脚本电子化，建立可复用的脚本模板库。

| 功能点 | 详细描述 | 优先级 |
|--------|---------|--------|
| 模板分类管理 | 按四大专业分类：电气系统 / 暖通系统 / 弱电系统 / 消防系统 | P0 |
| 模板列表展示 | 表格/卡片展示所有脚本模板，显示名称、分类、适用设备类型、版本号 | P0 |
| 新建脚本模板 | 通过表单或 JSON 定义脚本字段结构 | P0 |
| 字段构建器 | 可视化配置脚本字段：文本 / 数字 / 日期 / 下拉选择 / 单选/多选 / 数据表格 / 签字区 | P0 |

## 项目推进建议

### 阶段推进节奏

```
第一阶段  →  上线评审  →  第二阶段  →  上线评审  →  第三阶段  →  上线评审  →  第四阶段  →  正式验收
  18天         1天           18天          1天            15天          1天          22天           3天
  ↓            ↓             ↓            ↓              ↓             ↓            ↓            ↓
 内部试用   收集反馈      内部试用     收集反馈        内部试用     收集反馈      UAT测试      正式上线
```

### 关键成功因素

1. **业务侧深度参与**：每个阶段结束时，业务方必须参与评审，及时发现需求偏差
2. **渐进式推广**：每阶段上线后先内部试用，再逐步推广到全员，避免大规模推行风险
3. **文档同步**：每个功能上线，同步更新操作手册，减少后续培训成本
4. **数据质量优先**：第三阶段数据迁移时务必双人核对，确保历史数据不丢失、不出错
