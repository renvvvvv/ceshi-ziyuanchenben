# 测试策略与项目管理

> 加载规则：用户问"策略 / 计划 / 风险 / 进度 / 排期 / 验收 / 交付 / Go-NoGo"时读本文件。

---

## 一、测试策略金字塔

```
        验收测试（用户视角）
       ┌──────────────┐
       │   系统测试      │   ← 功能、性能、可靠性、能耗
       ├──────────────┤
       │   集成测试      │   ← 设备间联动、组网、液冷管路
       ├──────────────┤
       │   组件测试      │   ← 电源、风扇、传感器
       ├──────────────┤
       │   单元测试      │   ← 单板级
       └──────────────┘
```

**经验法则**：越底层问题越多，但单次成本低；越顶层问题越少，但修复代价大。所以底层要"撒网"，高层要"精打"。

## 二、测试阶段与典型用例

| 阶段 | 必测项 | 选测项 |
|---|---|---|
| **来料抽检** | 外观、序列号、固件版本一致性 | 关键器件批次追溯 |
| **单机测试** | 上电、BIOS、BMC、OS 安装、单机满载 | 噪音、振动、功耗曲线 |
| **组网测试** | 集群建链、BIOS 一致性、统一升级 | 大规模 RDMA 测试 |
| **液冷联调** | 漏液检测、温度平衡、压力曲线 | 长期腐蚀测试 |
| **业务压测** | 业务模型回放、稳定性跑分 | 混沌工程 |
| **验收交付** | 资料归档、培训、备件、应急预案 | 第三方测评 |

## 三、风险管理（核心模块）

### 风险登记表模板

| ID | 风险描述 | 概率 | 影响 | 等级 | 缓解措施 | 负责人 | 状态 |
|---|---|---|---|---|---|---|---|

| R02 | 液冷 CDU 长 lead time | 中 | 高 | 高 | 提前 6 个月下单、备用供应商 | 李四 | 关闭 |
| R03 | 机柜工艺一致性 | 中 | 中 | 中 | 抽检 10%、FMEA | 王五 | 跟进 |

### 风险等级计算

- **严重**：发生概率 > 50% 且影响 > 1 周延期
- **高**：概率 > 30% 或影响 > 1 周
- **中**：概率 10–30% 或影响 3 天–1 周
- **低**：可接受风险，定期回顾

### 常见高风险清单（数据中心测试项目）

1. **国产化器件一致性**——批次性问题最难追
2. **液冷首台套**——冷板贴合、二次侧洁净度
3. **长 lead time 物料**——CDU、冷板、特殊光模块
4. **固件版本"碎片化"**——不同批次固件不一致
5. **测试环境与生产环境差异**——功率、冷却、网络拓扑
6. **人员流动**——关键经验在少数人脑子里
7. **验收标准模糊**——客户/厂商/集成商三方认知不齐

## 四、缺陷管理

### 严重等级定义

| 等级 | 定义 | 响应时间 | 解决时间 |
|---|---|---|---|
| **P0** | 业务中断/数据丢失/安全风险 | 1h | 24h |
| **P1** | 主要功能不可用 | 4h | 72h |
| **P2** | 次要功能受影响 | 24h | 1 周 |
| **P3** | 界面/优化建议 | 1 周 | 下个版本 |

### 缺陷状态机

```
新建 → 已分配 → 已修复 → 已验证 → 已关闭
                  ↓
              重新打开（验证不通过）
```

### 缺陷归零标准

- **遗留缺陷评估**：所有 P3 及以上缺陷必须经客户/PM 签字接受
- **修复率要求**：P0 100%、P1 ≥ 95%、P2 ≥ 85%、P3 ≥ 60%
- **回归测试**：必须覆盖所有已修复缺陷所在模块

## 五、验收与交付

### 验收三段式

1. **预验收**（内部）：所有用例通过 + 缺陷归零报告
2. **正式验收**（客户）：按合同验收清单逐项确认
3. **试运行**（1–4 周）：真实负载观察，遗留问题闭环

### 交付物清单

- 测试方案 / 测试用例 / 测试报告
- 缺陷清单与归零报告
- 性能/能耗基线数据
- 设备配置文件（BMC、BIOS、网络）
- 应急预案
- 培训记录
- 备品备件清单
- 第三方测评报告（如有）

### 验收常见坑

1. **验收清单模糊**——签字时扯皮，必须事前逐条对齐
2. **样机 vs 量产机差异**——验收时必须抽量产机
3. **测试环境 ≠ 生产环境**——功率、冷却、拓扑差异导致表现不同
4. **第三方测评费用**——预算与责任需事前明确
5. **知识产权**——测试脚本、数据归属提前约定

## 六、Go/No-Go 决策框架

### 决策清单

| 维度 | Go 标准 | No-Go 信号 |
|---|---|---|
| **测试完成度** | 用例执行率 100%、通过率 ≥ 95% | P0 缺陷未关闭 |
| **性能** | 达到 SPEC 或合同约定 ±5% | 波动 > 10% 或低于基线 10% |
| **可靠性** | MTBF 预测值 ≥ 50 万小时 | 连续重启 / 硬件错误 |
| **能耗** | PUE ≤ 设计值 + 0.05 | 超设计值 0.1 |
| **缺陷** | P0/P1 全关，P2 评审通过 | P0/P1 未归零 |
| **文档** | 完整、可追溯 | 缺失关键章节 |

### 决策会议要点

- 三方（厂商/集成商/客户）必须全部到
- 数据为王，**不要靠感觉决策**
- 任何分歧都要落到书面记录
- No-Go 必须附"达到 Go 的具体条件"和时间表

## 七、测试团队管理

### 角色与职责

| 角色 | 职责 |
|---|---|
| **测试经理** | 策略制定、风险管控、跨方协调、汇报 |
| **架构师/技术负责人** | 测试方案评审、技术决策 |
| **测试工程师** | 用例执行、缺陷管理、数据采集 |
| **自动化开发** | 工具链、脚本、数据分析平台 |
| **NRE（新产品导入）** | 厂商与现场衔接、首台套验证 |

### 团队效率指标

- 人均用例执行数 / 周
- 缺陷发现密度
- 测试周期 vs 计划偏差
- 自动化覆盖率（持续提升）

## 八、项目复盘

### 复盘四问

1. **目标 vs 结果**：当初定的目标达成了吗？
2. **关键事件**：哪些决策对结果影响最大？
3. **根因**：成功/失败背后的根因是什么？
4. **下一步**：沉淀什么经验、改进什么流程？

### 复盘输出

- 复盘报告（内部分享）
- SOP 更新（流程沉淀）
- 知识库新增条目
- 工具/脚本归档

## 九、给项目经理的常见提醒

1. **计划要留 20% buffer**——机房现场永远比想象多 1 周
2. **关键路径要每日跟进**——液冷联调、长 lead time 物料是常见瓶颈
3. **沟通频率要高于客户预期**——主动同步比被动解释强 10 倍
4. **数据可视化**——周报用图表比文字强
5. **重视"软"风险**——人员、士气、跨方关系同样是延期原因
