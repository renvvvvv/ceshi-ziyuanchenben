# 现场排障方法论

> 加载规则：用户问"现场 / 故障 / 告警 / 异常 / 不收敛"时读本文件。

---

## 一、六步法（必走流程）

```
现象 → 假设 → 验证 → 根因 → 缓解 → 根治
```

**严禁跳过"验证"直接给根因**。现场翻车 80% 是因为猜得太快。

---

## 二、分层假设矩阵（OSI 现场版）

| 层级 | 检查项 | 工具 |
|---|---|---|
| **L0 物理/动力** | 供电、PDU、UPS、电池 | 万用表、PDU 显示屏、BMC SEL |
| **L1 环境** | 温度、湿度、露点、气流 | 温湿度计、热像仪、风速计 |
| **L2 设备** | 风扇、PSU、散热器、插槽 | BMC、ipmitool、肉眼+手摸 |
| **L3 链路** | PCIe、NVLink、网络、SAS | lspci、nvidia-smi topo、交换机命令 |
| **L4 平台** | BIOS、BMC、驱动、固件 | dmidecode、ipmitool、版本矩阵 |
| **L5 负载** | OS 调度、NUMA、IRQ | perf、numastat、taskset |

**经验法则：先下后上**——先排除动力/环境/物理，再往上走。

## 三、十大高频故障剧本

### 1. PUE 突增

**判定**：PUE = 总输入 / IT 负载，正常 1.3–1.5；突增 > 0.1 即异常。

**假设（按概率）**：
1. IT 负载下降（分母变小）→ 看机柜级 PDU 是否同步下降
2. 冷却系统效率下降 → CDU 出水温度升高、流量下降
3. 外部环境恶化 → 湿球温度升高、冷塔风机频率拉满
4. UPS 切换 ECO/在线模式 → 效率变化 2–4%

**现场 3 步**：
1. `ipmitool ... sdr list | grep -i "input\|power"` 看各机柜功耗
2. 读 CDU 一二级进出水温度与流量
3. 查天气记录、湿球温度、冷塔运行日志

**验证标准**：PUE 回到基线 ± 0.03 且维持 24h。

---

### 2. CPU/GPU 压测性能不达标

**假设**：
1. 散热限频（最常见）→ 进风温度高 / 风扇策略 / TIM 失效
2. BIOS 电源策略 → PL1/PL2/Tau 设置不合理
3. NUMA 跨节点 → 内存访问延迟翻倍
4. 频率被锁 → C-State、SpeedStep、P-State 状态

**现场 3 步**：
1. `sensors` + `turbostat` 看 CPU 是否频繁撞温度墙或 PL1
2. `lscpu | grep "NUMA"`，确认进程是否绑核
3. BIOS 里看 PL1/PL2/Tau 值，与厂商推荐值对比

**验证标准**：连续 3 次跑分波动 < 2%，达到 SPEC 或厂商公布值的 95% 以上。

---

### 3. GPU 掉卡

**假设**：
1. PCIe 链路不稳 → 背板固件、Re-timer
2. 电源跌落 → PSU 老化、PDU 闪断
3. 散热失效 → 冷板流量下降、风扇故障
4. 驱动不兼容 → 升级或回退

**现场 3 步**：
1. `nvidia-smi -q | grep -A 5 "GPU Lost"` 看掉卡时间戳
2. 同一时间窗查 BMC SEL 的 PCIe/PSU 事件
3. 重启前后用 `lspci -vvv` 看链路速率

**验证标准**：连续 72h 满载不掉卡，`nvidia-smi -q -d ECC` 无新增 DBE。

---

### 4. 液冷漏液告警

**假设**：
1. 快速接头 O 圈老化或未压紧
2. 二次侧凝露（误报）
3. 冷板内部渗漏
4. 传感器本体故障

**现场 3 步**：
1. 立即隔离：关闭故障机柜进液阀，保留出液侧
2. 物理检查：接头处纸巾擦拭+放大镜看水迹
3. 压力测试：保压 30 min，看压降是否 > 0.2 bar

**验证标准**：连续 7 天无漏液告警，CDU 压差稳定。

**风险**：漏液未隔离可能引发短路和地板塌陷，必须物理隔离 + 通知运维。

---

### 5. PCIe 协商速率降级

**假设**：
1. 背板/线缆信号完整性差
2. 设备端 Re-timer 故障
3. BIOS 强制降速
4. 槽位与 CPU 直连/跨 NUMA 拓扑差异

**现场 3 步**：
1. `lspci -vvv -s <BDF> | grep -i "link speed\|width"` 看实际协商
2. 换槽位重测，看是否复现
3. 升级背板/BMC 固件到推荐版本

**验证标准**：协商速率达到设计值，连续 100 次识别稳定。

---

### 6. 网络抖动 / 丢包

**假设**：
1. 光模块衰减或污染
2. PFC/ECN 配置不当引发风暴
3. 路由震荡或 ECMP 不均
4. 交换机 ACL/流控

**现场 3 步**：
1. `show interface counters errors` 看 CRC、丢包、输入错误
2. `show interface transceiver` 看光功率（Tx/Rx 偏差）
3. 拔掉嫌疑端口 ping 测试

**验证标准**：连续 ping 1 分钟丢包率 < 0.001%，时延稳定。

---

### 7. 压测中系统重启

**假设**：
1. 散热撞墙触发紧急关机（最常见）
2. 电源 PSU 容量不足
3. BMC/BMC watchdog 误触发
4. 内存/PCIe 硬件错误（MCE/AER）

**现场 3 步**：
1. 立即采集 `mcelog`/`rasdaemon`、`journalctl -b -1`、BMC SEL
2. 查重启前 5 分钟的温度/功耗/风扇日志
3. 隔离硬件：换内存、换槽位、换 PSU 复测

**验证标准**：连续 24h 满载无重启，SEL 无新增硬件错误。

---

### 8. BMC/IPMI 失联

**假设**：
1. 网络抖动（共享口/VLAN）
2. BMC 固件死机（最常见）
3. IP 冲突
4. 带外管理交换机故障

**现场 3 步**：
1. 笔记本直连 BMC 口，看是否能 ping 通
2. IPMI 重启：`ipmitool -I lanplus ... mc reset warm`（需先能通）
3. 完全不通则需现场硬重启（拔插 BMC 板/整个 PSU 拔插 30s）

**验证标准**：带外管理连续 7×24h 在线，告警可达。

---

### 9. PUE 异常但设备温度正常

**假设**：冷源效率下降（冷塔、冷冻水主机、CDU 老化）
**现场 3 步**：
1. 读冷塔风机频率、冷冻水进出温差
2. 读 CDU 一级水温与二级温差
3. 对比上月同期冷源效率曲线

**验证标准**：冷源 COP 回到设计值 ± 5%。

---

### 10. 验收过程中批量设备出现共性问题

**假设**：
1. 固件/驱动版本不一致
2. 批次性硬件缺陷
3. 测试环境配置漂移
4. 测试方法本身缺陷

**现场 3 步**：
1. 抽样 3 台比对 BMC SEL、固件版本、错误日志
2. 复现测试用例，看是否 100% 复现
3. 与厂商现场工程师同步，提交 8D 报告

**验证标准**：缺陷归零报告 + 同批次 100% 抽检通过。

## 四、现场排障黄金法则

1. **先恢复后定位**——能重启就重启，能切旁路就切旁路，别在业务中断时研究根因
2. **一次只改一个变量**——同时改 BIOS + 网络 + 驱动，你会搞不清是谁修好的
3. **所有操作必须能回退**——截图 BIOS 现状、备份配置
4. **记录到分钟级**——SEL 时间戳与人工记录要交叉对得上
5. **不要迷信单点指标**——温度正常不代表风扇正常，温度告警不代表根因就在温度
6. **拉通是责任，不是义务**——跨域问题拉上网络/动环/应用一起看

## 五、需要立刻升级的场景（不要硬扛）

- 同一机柜 3 台以上同时异常
- 冷却液位快速下降或 CDU 持续补液
- UPS 切旁路告警
- 机房消防/温感/烟感联动
- 任何涉及人身安全的高压/高温/化学品场景

这些场景下，**先保人保设备，再找根因**，通报主管与厂商同步启动应急流程。
